# 可直接发给其他任务的发布要求

请把当前游戏做成朋友打开 HTTPS 链接就能玩的网页试玩版，并同步到我的 GitHub。请实际完成构建、安全检查、发布和公网试玩验证。

1. 先检查当前游戏的引擎、项目根目录、已有 Git 仓库和发布方式。每款游戏使用独立目录、独立仓库和独立网站路径；已有合适仓库就沿用。不要提交父目录、混入其他项目、覆盖其他网站或修改其他仓库的远程地址。
2. 我同意为这款游戏建立公开仓库并发布可试玩版本。只公开有权发布的源码和素材；先检查素材授权与再分发限制。若存在无法公开的内容，说明具体问题并先完成不受影响的准备工作。不要默认开放 Issues 以外的额外服务或购买付费资源。
3. Unity 项目优先构建 WebGL，其他引擎选择对应的网页导出。纯前端游戏优先放在 GitHub Pages；包含服务器、联机、登录、付费功能时，先说明后端部署和权限方案，不要把服务器密钥放进网页，也不要把我家电脑或局域网服务暴露到公网。
4. 发布前检查源码、Git 历史及最终构建包是否含令牌、密码、私钥、个人资料或本地配置，排除缓存、日志和无关文件；检查依赖风险与素材许可证。凭据使用系统授权或安全存储，不在输出中展示。发现已经泄露的凭据时明确报告需要撤销和更换，不能只删除当前文件就当作解决。
5. 发布工作流使用最小权限；第三方 Actions 固定到经过验证的完整提交版本，避免不受信任的代码接触发布凭据。按引擎实际需要设置兼容的 CSP、资源完整性校验等保护，并验证它们不会阻止游戏、音频和 WebAssembly 运行。不要为了消除报错一概关闭保护。
6. 为构建资源使用版本路径或内容哈希，避免旧缓存混用新旧代码。建立可复现的构建记录和回滚方法，保留正确的源码版本与正式下载包对应关系，不要把仅更新网页的版本误标成已经更新原生安装包。
7. 真实打开最终公网链接测试加载、开局、战斗、声音、暂停和重新进入。支持手机时检查触控、横竖屏、画面比例及性能；明确哪些是设备模拟，哪些经过实体设备测试。检查网页请求不会误连 localhost 或私人服务。
8. 完成后给我稳定的试玩链接、仓库地址、更新方法、回滚方法和检查结果。说明仍存在的具体限制，不要宣称绝对安全，也不要只建立一个空仓库或只给我操作教程。

## 适用范围

GitHub Pages 是静态网站托管，适合纯客户端网页游戏；服务器逻辑需要另外部署。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

最小权限、妥善保存凭据与固定 Actions 版本依据 [GitHub 工作流安全说明](https://docs.github.com/en/actions/reference/security/secure-use)。这些措施降低风险，不能保证零漏洞或阻止他人下载公开的网页资源。
